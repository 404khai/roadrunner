# Phase 33 — finite performance engineering tranche

The accepted [Q1–Q18 architecture contract](performance/architecture-contract.md)
governs this implementation. Phase 34 has a [reviewable plan](performance/phase34-plan.md)
and remains separately authorized; no target fleet capacity is claimed.

## Delivered scope

1. **Bounded, reproducible diagnostic probes**, in the simulation example rather than
   a generic production tracing system: graph clone/encode/decode, prepared routing,
   validation/snapshot/candidate construction and real engine simulation/capture.
   Ten manifest-qualified cases include a pinned road artifact, two synthetic routing
   sizes, fresh/aged candidate populations, headless trace growth and context churn.
2. **Exact-snapshot eligibility validation reuse.** Candidate generation consumes the
   immutable constructor-validated snapshot proof. The defensive public WorldData
   helper still validates; rider-specific checks and current-authority commit remain.
3. **Shared original action traffic.** The engine retains one full ordered vector
   per currently materialized graph-qualified traffic context, shared by original
   actions through `ActionTraffic`. Context replacement never mutates old vectors.
   Deserialized/edited artifacts remain independent through copy-on-write.
4. **Semantic comparison tooling and CI smoke**, with no timing threshold. The
   collector rejects missing/mismatched reference manifests/graphs/full-result hashes.
   Negative comparison tests reject tampered samples and incomplete workload coverage.
5. **Retained raw measurements, overload/correctness contract, risk register and
   Phase 34 generator/harness entry plan**. No new dispatch, retention, archive,
   publication, worker-admission or cancellation policy is introduced.

## Evidence and measured results

The [evidence brief](performance/phase33-evidence-brief.md) predates implementation.
[Control](../benchmarks/results/phase33-control.json) uses source `d265c05`;
[candidate](../benchmarks/results/phase33-candidate.json) uses `0ebc114`. Explicit
binary hashes, source/collector revisions, manifests, semantic graph hashes, compiler,
OS/CPU/memory and raw repetitions are retained. The earlier validation-only artifact
isolates the first optimization. [Comparison](../benchmarks/results/phase33-comparison.json)
is generated by `scripts/compare_phase33.py`, not hardcoded conclusions.

Seven measured fresh-process runs follow one excluded warmup per case, release Rust
1.99.0, concurrency one. No builds/tests ran in the control/candidate collection
intervals. The host was not exclusive; background activity remains uncontrolled.
Stages and whole-process times are separate. Quantiles describe these small samples,
not individual route/dispatch request tails or SLOs. Cache state is warm/uncontrolled
OS/filesystem state, not a cold-load result. See [reproduction/methodology](../benchmarks/phase33/README.md).

Descriptive medians (candidate timings each cover **five calls**, excluding snapshot
construction; simulation timings exclude graph setup and separate JSON encoding):

- `candidates-aged128` / `exhaustive_ns`: 88.613 → 0.352 ms.
- `candidates-aged128` / `spatial_eligibility_build_query_ns`: 88.117 → 0.458 ms.
- `candidates-fresh64` / `exhaustive_ns`: 0.778 → 0.021 ms.
- `candidates-fresh64` / `spatial_eligibility_build_query_ns`: 0.849 → 0.083 ms.
- `simulation-grid32` / `execution_ns`: 97.409 → 86.515 ms.
- `simulation-grid32` / `serialization_ns`: 65.219 → 60.552 ms.

In the 1,024-node/3,968-edge, one-rider/128-order headless case, 256 starts retain
**1,015,808 logical traffic entries before and after**. Distinct buffers fall from
256 to 1; vector-element capacity falls from 16,777,216 bytes (16 MiB) to 65,536
bytes (64 KiB). These are live Vec element capacities, excluding allocator/Arc
headers and all other data. Whole-process median peak RSS falls from 64,405,504
to 45,350,912 bytes; RSS includes graph preparation, simulation, full JSON output
and diagnostics, so it is not an allocator attribution or a universal ratio.

Every repetition of all ten cases matches the same baseline/candidate semantic
SHA-256. Full SimulationResult bytes/size stay identical, including started traffic,
original routes, effects, schedules, decisions and scenes. The serialized traffic
payload remains logically A×E; this change reduces internal physical duplication,
not wire size, export peak guarantees or historical retention obligations.

Unchanged routing/graph probes are controls, not claimed improvements. A* remains
slower than Dijkstra on these grid queries; this is fixture-specific evidence, not
a general algorithm ranking. Durable throughput is not inferred from these probes.

## Instrumentation accuracy and negative findings

Stage clocks and optional post-execution buffer inventory exist only in the example;
normal library calls acquire no performance timers or diagnostic inventory. Canonical
expanded-state counters, budget units and portable evidence identities are unchanged.
The inventory measures actual unique live vector element capacity; it does not measure
allocator call counts, shared Arc headers or per-query RSS. Coarse OS process CPU
seconds are recorded when available, not per-stage CPU attribution.

[Enabled/disabled inventory runs](../benchmarks/results/phase33-instrumentation.json)
produce identical full-result hashes. Whole-process medians are 118.014/147.002 ms
(off/on), while samples vary up to 1.381 seconds and stages before the inventory also
slow. This experiment is **inconclusive for observer overhead**; the difference cannot
be attributed to the small inventory. RSS medians differ by 16 KiB, not a precise
added-allocation result. Per-operation allocator observations remain unavailable.
No claim of zero-cost production telemetry or low-overhead generic instrumentation
is made. Profiling-mode timings must not become service performance claims.

## Compatibility and proof

`ActionTraffic` replaces the public Rust field's Vec type with a transparent shared
wrapper. Its serialized form is exactly the original ordered array; `Deref`/copy-on-
write `DerefMut` preserve reads and isolated artifact edits. Rust callers constructing
StartedAction directly from a Vec use `.into()`. There is no artifact/wire migration,
no source change to the public eligibility helper and no global validation certificate.

New tests compare snapshot eligibility against the defensive helper and linear spatial
oracle across equal identity/version worlds, availability masks, corrupt relationships,
wrong graph anchors and assignment-only changes. Traffic tests cover shared storage,
context churn, original factor retention, exact array round-trip and independent edits.
Existing independent routing/planning, frozen execution, dataset and byte-replay tests
remain authoritative. Changed paths do not modify fleet/recovery candidate order,
submission budgets, stage authority, arrival/completion or accepted terms.

## Remaining measured and unmeasured limits

Measured costs remain: graph decoding/encoding, full result serialization and retained
history. The grid and 58-node road cases do not qualify city topology or demand.
The 128-rider candidate probe is not a 128-rider operational throughput result.

Deferred: per-query allocator/CPU sampling, scratch reuse, persistent spatial indexes,
prepared API heuristics, decision-local leg caching, unchanged-plan reuse, recovery
materialization, whole-world copies, durable graph ownership/image/SQL optimization,
coordinator/anchor timing, bounded route waiting and cooperative cancellation.

Scene limits (32 riders/64 orders/2K queue entries), ordinary HTTP input caps,
checkpoint-v1 complete history, command recognition, SQL/fsync/anchor guarantees and
single-writer authority remain. No global graceful OOM handling, new archive/compaction,
VRP optimum, production SLO or Tier A/B/C support is claimed.

## Completion and entry gate

The declared two-change tranche has reproducible source-qualified baselines, justified
selection, matched semantic/performance evidence, regression checks and explicit gaps.
It does not optimize every component. Review this package and the Phase 34 plan before
separately authorizing workload-generation and stress implementation. Newly exposed
constraints require scoped remediation, not an automatic rewrite or raised limits.
