# Roadrunner v0.1.0 — engineering preview

This release scope brings together the implemented routing, dispatch, simulation,
visual debugging and documentation workflows. Package versions already identify
0.1.0; this work does not create a release tag or assert Phase 40/v1.0 readiness.
A PR still requires its normal CI and maintainer review before release.

## Scope limitations

- This is an engineering preview, not a production dispatch service or Google Maps
  replacement. Authentication/authorization follows the documented configured API
  credentials; this is not a customer account/billing system.
- Traffic and demo movement are synthetic/estimated. There is no physical GPS feed,
  production traffic ingestion or fabricated telemetry. Ambient visual vehicles
  are separate from authoritative delivery riders.
- OSM and turn restrictions enforce a declared supported subset. Unsupported forms
  remain explicit. Snapshot-local anchors cannot be substituted across graphs.
- Fleet/recovery planning is heuristic and budgeted, without global VRP optimality.
  Incomplete search, infeasibility, stale publication and uncertain durable outcomes
  retain distinct meanings.
- The visual capture path remains bounded to 32 riders/64 orders/2,000 processed
  entries and 8 MiB output. The demo does not increase these limits or prove city-scale
  browser performance. Phase 34's tier targets remain qualified investigations;
  consult its actual failures and successful workload definitions.
- Offline learned ETA has not earned operational integration. Rust routing and
  dispatch require neither Python nor a learned model.
- PostgreSQL is optional for local demos. Durable guarantees require the documented
  storage/anchor/fencing configuration and restoration checks, not just an API process
  remaining alive. Kafka and Redis are not prerequisites.

## Validation and release boundary

Use the [completion record](phase-38-39-completion.md) for this change's verification.
Ordinary CI additionally covers workspace formatting/Clippy/tests, PostgreSQL/PostGIS
transaction/crash recovery, learned-evidence oracles and benchmark contracts. Local
fleet replay and browser tests do not replace those jobs. No new latency SLA, supported
maximum fleet, production durability certification or graceful OOM guarantee is claimed.
